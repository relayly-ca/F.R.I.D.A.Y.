# Week 4 — four more senses, one at a time, and speech

Spec section 6, week 4 and the first half of the 4-5 row:

> notmuch, files, browser, Home Assistant — eval score holds after each new source
> Voice: Whisper → Kokoro, wake word + clap, speaker ID — under 800ms, hands-free, voice-gated

The wake path, the clap, and the speaker gate are W5. This week is the four sources and the
two ends of the audio pipeline.

## Goal

Add four sources without losing the retrieval quality you spent week 3 earning, and get
speech in and speech out working as a plain request-response before any of the hands-free
machinery is built on top of it.

The done-when for the sources is not "they are ingesting." It is **"eval score holds after
each new source."** That is a per-source gate, and it is the whole reason this week is
structured as four separate passes rather than one enable-everything commit. A new corpus can
drag retrieval down by five points, and if four arrived together you cannot tell which.

## Done when

1. `mbsync` and `notmuch` are syncing and indexing, and mail is in the index.
2. Files, browser history, and Home Assistant are each ingesting.
3. `make eval` scored 20 or better **after each of the four**, recorded in `eval/results/`,
   with four separate result files you can point at.
4. No credential material is in the index. You have checked, not assumed.
5. `friday speak "..."` produces audio out of the speakers through Kokoro.
6. `friday listen --once` transcribes you through faster-whisper large-v3-turbo.
7. Round-trip latency is measured and written down, even though it will not meet 800ms yet.
8. `make known-good` succeeds again at the end of the week.

## Prerequisites

- W3 complete, `make eval` at 20 or better, `known-good` tagged.
- A working microphone and speakers. `arecord -l` and `aplay -l` list devices.
- A mail account you can sync with `mbsync`, and its credentials in sops rather than in a
  config file.

## Steps

### 1. The gate, before any of them

Record the baseline you are protecting. Everything below is measured against this number.

```bash
make eval
cp eval/results/$(ls -1t eval/results | head -1) eval/results/baseline-w4.json
```

The loop for each of the four sources, in this order:

```
enable one source  →  backfill  →  reindex  →  make eval  →  20 or better?
    yes → commit, move to the next source
    no  → diagnose with --explain, fix, re-run. Do NOT enable the next source.
```

Order matters: mail first because it is the largest and most likely to cause a problem, files
second because the exclusion rules are a security control, browser and Home Assistant last
because they are small and mostly harmless.

### 2. Mail

Spec section 1: mbsync + notmuch. mbsync syncs, notmuch indexes, and we read the notmuch
index. Network handling and credentials stay entirely out of the FRIDAY process — that is the
point of the split, and it is ADR-0005 applied to mail.

```bash
sudo pacman -S --needed --noconfirm isync notmuch python-notmuch
sudo install -d -m 0700 -o friday -g friday /srv/friday/db/mail
```

Credentials via a sops-backed helper. `mbsync` calls `PassCmd`, which invokes the helper,
which decrypts. The password never lands on disk in cleartext and never enters an environment
variable that shows up in `/proc`.

```bash
sudo sh -c 'umask 077; printf "MAIL_PASSWORD=%s\n" "$(read -rsp "imap password: " p; echo "$p")" > /tmp/mail.env'
sudo sh -c 'SOPS_AGE_KEY_FILE=/srv/friday/secrets/age.key sops --encrypt /tmp/mail.env > /srv/friday/secrets/mail.env.sops'
sudo shred -u /tmp/mail.env
```

```bash
sudo -u friday tee /srv/friday/db/.mbsyncrc > /dev/null <<'EOF'
IMAPAccount main
Host           # VERIFY: your IMAP host
User           # VERIFY: your address
PassCmd        "/srv/friday/bin/secret-helper mail_password"
TLSType        IMAPS
CertificateFile /etc/ssl/certs/ca-certificates.crt

IMAPStore main-remote
Account main

MaildirStore main-local
Subfolders Verbatim
Path   /srv/friday/db/mail/
Inbox  /srv/friday/db/mail/INBOX

Channel main
Far  :main-remote:
Near :main-local:
Patterns *
Create Near
SyncState *
EOF
sudo -u friday mbsync -c /srv/friday/db/.mbsyncrc -a
```

```bash
sudo -u friday notmuch --config=/srv/friday/db/.notmuch-config new
sudo -u friday notmuch --config=/srv/friday/db/.notmuch-config count '*'
```

Then enable the source. `config/sources.yaml` already sets the important defences and they
are not negotiable:

- `fetch_remote_content: false`. Remote images and followed links are exfiltration channels,
  and neither is needed to index text. A tracking pixel in a 3am email is a beacon that
  confirms your agent read it.
- `index_attachments: false`. Attachment names, not contents. Parsing an attacker-supplied
  PDF means running a parser with a CVE history against hostile input, on the box that holds
  everything.

```bash
sed -i 's/^  notmuch:\(.*\)$/  notmuch:\1/' config/sources.yaml   # no-op; edit enabled: by hand
${EDITOR:-nano} config/sources.yaml     # notmuch.enabled: true
uv run python -m friday.ingest.notmuch --once
uv run python -m friday.memory.ingest --from-sources
uv run python -m friday.memory.index --reindex-new
make eval
```

Mail is `sensitivity: messages`, which pins local by ADR-0008, and it is the single largest
untrusted-input surface in the system. Spec section 9's framing is exact: an email she reads
at 3am is untrusted input with a path to your shell. In week 4 there is no shell for it to
reach. In week 5 there will be, which is why the container and the supervisor arrive
together.

Expect the eval to move. Mail is a lot of text and much of it is noise; if the score drops,
the fix is usually the notmuch query, not the retrieval parameters:

```bash
# config/sources.yaml: query: "not tag:spam and not tag:deleted"
# Tighten it. Newsletters and automated mail are pure retrieval noise.
```

### 3. Files

The exclusion list is a security control and not a performance one. ADR-0005 says it
directly: indexing a key routes around capabilities-not-credentials entirely, because any
query could then surface it into a context window.

```bash
${EDITOR:-nano} config/sources.yaml     # files.enabled: true, check roots and exclude_globs
uv run python -m friday.ingest.files --once --dry-run | head -50
```

Read that dry-run output. Actually read it. It is the last moment before your SSH keys, your
`.env` files and your password manager export enter a searchable index that a model reads
from.

```bash
uv run python -m friday.ingest.files --once
uv run python -m friday.memory.index --reindex-new
make eval
```

Then check, rather than assume:

```bash
uv run python -m friday.memory.retrieve --query "BEGIN PRIVATE KEY" --explain
uv run python -m friday.memory.retrieve --query "AKIA" --explain
uv run python -m friday.memory.retrieve --query "password" --explain
sqlite3 /srv/friday/db/episodic.db \
  "select source, external_id from episodic where body like '%PRIVATE KEY%' or body like '%BEGIN OPENSSH%';"
```

Any hit is a finding. Purge it from the episodic log and Qdrant, fix `exclude_globs`, and
re-run. A secret that reaches the index is not fixed by rotating the secret alone — the
index has to be cleaned too.

`suppress_during_consolidation: true` matters here: the vault is a watched root and the
consolidation loop writes to it. Without suppression the index fills with copies of itself,
which shows up as an eval score that drifts down over days with no change to explain it.

### 4. Browser

```bash
${EDITOR:-nano} config/sources.yaml     # browser.enabled: true
uv run python -m friday.ingest.browser --once
uv run python -m friday.memory.index --reindex-new
make eval
```

`copy_before_read: true` — `places.sqlite` is locked while Firefox runs. Copy, read, delete
the copy.

URL, title and visit time only. **Never refetch a page.** Refetching is egress, it tells the
site your agent visited, and weeks later you get what the site serves a bot rather than what
you actually read. `exclude_url_patterns` drops banking and health by default; extend it
before you enable this, not after.

### 5. Home Assistant

```bash
# VERIFY: install method. Container or supervised, bound to 127.0.0.1:8123.
${EDITOR:-nano} config/sources.yaml     # homeassistant.enabled: true
```

The token goes in sops and reaches the unit by env var name (`HASS_TOKEN`), never by value.
A long-lived HA token is a capability over your house; treat it like one.

```bash
uv run python -m friday.ingest.homeassistant --once
make eval
```

`mode: websocket`, not polling — polling a state machine misses transitions, and the
transitions are the whole signal. `entity_exclude: ["camera.*"]`: frames are not text.
Cameras belong to the `vision` alias, not to ingestion.

Home Assistant is also the device control plane for the voice satellites (ADR-0016), so flash
one now while you are here. It is the room you will test W5's clap detection in.

```bash
# VERIFY: ESPHome install method - HA add-on or standalone container.
# One ESP32-S3 board, I2S microphone, small speaker, permanently powered.
esphome run satellites/study.yaml
```

The satellite captures and streams. It does not transcribe, holds no model, and runs no wake
word that matters — ADR-0018, one STT process on the server's GPU. That is what keeps a
satellite cheap enough to put in four rooms and replaceable by anything else that speaks
ESPHome.

Every room's audio now crosses the network to one box. That network is the mesh and never the
internet (spec section 9), and it is worth saying plainly: this is a microphone array in your
house.

While you are here, bring up `vision` on 8084, since it is the alias any camera or screenshot
work will use:

```bash
sudo tee /etc/friday/llama/vision.env > /dev/null <<'EOF'
MODEL=/srv/friday/models/vision.gguf
PORT=8084
ARGS=--ctx-size 8192 --n-gpu-layers 999 --alias qwen3-vl
EOF
sudo systemctl enable friday-llama@vision    # enable, do not start: on demand, it evicts daily
```

### 6. Speech in

```bash
uv sync --extra voice
sudo pacman -S --needed --noconfirm sox alsa-utils
arecord -l
```

faster-whisper large-v3-turbo, spec section 1. It is part of the ~6 GB resident set alongside
the router, bge-m3, the reranker and Kokoro — so it loads once and stays loaded. Loading it
per utterance costs more than the whole latency budget.

ADR-0018 settles the model size before you are tempted by it in step 8: `large-v3-turbo`
stays, on the GPU, and there is exactly one STT process in the whole system. The smaller
`base.en` is the answer to CPU inference, and with the GPU in play the problem it solves does
not exist — STT is 100-250ms of the 800ms budget and end-of-speech detection is the line item
that blows it. What `base.en` costs is proper nouns, and mishearing "Sam" as "Sarah" is not a
slightly worse answer, it is a confident retrieval against the wrong person's notes with
every layer below working correctly on a wrong premise.

```bash
uv run python -m friday.voice.stt --download        # first run fetches the model
uv run python -m friday.voice.stt --once            # speak; it prints the transcript
```

```bash
sudo systemctl enable --now friday-voice.service    # resident models, no wake path yet
```

`config/friday.toml` has `[voice] enabled = false`. Turn it on now and only now:

```bash
${EDITOR:-nano} config/friday.toml    # [voice] enabled = true
```

### 7. Speech out

Kokoro-82M is the fast default. Chatterbox-Turbo is the cloned voice for when it matters;
skip it this week.

```bash
uv run python -m friday.voice.tts --text "Ready." --play
```

`# VERIFY:` Kokoro's current install path. `pyproject.toml` lists `kokoro>=0.3` under the
`voice` extra; if the wheel is not on PyPI for your Python, install from git rather than
downgrading Python.

### 8. Measure the latency, and write it down

The budget is 800ms end of speech to first audio out (`latency_budget_ms` in
`config/friday.toml`). You will not meet it this week and that is fine — this week is about
knowing where the time goes, because in week 5 you have to find 400ms somewhere.

```bash
uv run python -m friday.voice.bench --turns 20
```

It must break the number down by stage, not report one total:

| Stage | Typical | Notes |
|---|---|---|
| End-of-speech detection | 100-300ms | VAD hangover. The largest and most tunable |
| STT | 100-250ms | large-v3-turbo, resident, batch of one |
| Retrieval | 50-200ms | Keyword and vector must be concurrent, W3 step 4 |
| Model turn to first token | 100-400ms | `fast`, not `daily`. `config/agents.yaml` |
| TTS to first audio | 50-150ms | Kokoro, streaming first chunk |

A single total tells you nothing. A breakdown tells you that VAD hangover is 400ms of your
800ms, which is the usual answer.


## Failure modes

**All four sources enabled in one commit, and the eval dropped six points.** You cannot
attribute it. The only real fix is to disable all four and redo the week one at a time, which
costs an evening — which is why the week is written this way.

**Mail drops the eval by four points and the retrieval parameters do not recover it.** Mail
is mostly noise. Tighten the notmuch query rather than the reranker; excluding automated mail
usually returns the whole four points.

**A private key in the index.** Rotate the key, and then purge the index — both. The
exclusion globs go in `config/sources.yaml`, which is where they are read from, not in a
`.gitignore`.

**The vault indexes itself.** `suppress_during_consolidation` off, or the vault root not
excluded during a consolidation run. The eval drifts down over days with no change to blame,
which is the hardest failure shape in this whole build to notice.

**Firefox is running and `places.sqlite` is locked.** `copy_before_read: true`. Never open
it directly.

**Whisper loads per utterance.** Every turn pays two seconds of model load. The service must
hold the model resident; `friday-voice.service` exists to be the thing that holds it.

**Kokoro's wheel does not exist for Python 3.12.** Install from git. Do not unpin Python.
`pyproject.toml` pins 3.12 deliberately (W1 step 4), and unpinning it to satisfy one TTS
package breaks every service on the next `-Syu`.

**Latency is 3 seconds and it is "all the model".** It is almost never all the model.
Measure per stage. VAD hangover and a non-resident STT model are the usual two, and both are
fixed without touching a model.

**Home Assistant polling misses the transition you cared about.** `mode: websocket`.

## Do not do yet

- **No wake word, no clap, no speaker gate.** W5. This week the voice path is triggered
  explicitly by you running a command.
- **Voice cannot do anything consequential.** `conversation` in `config/agents.yaml` has
  `can_write: false` and tools `[memory_read, calendar_read]`. Leave it there. Until the
  Resemblyzer gate exists in W5, anyone within earshot is an unauthenticated user.
- **No MCP tools, no OpenHands, no shell.** W5.
- **No supervisor.** W5. It arrives in the same week as the first write capabilities, which
  is not a coincidence.
- **No scrutiny.** W7.
- **Do not enable a fifth source** because it seemed easy. Every source is a week-4-shaped
  cost: enable, backfill, reindex, eval.
- **Do not skip the eval between sources** because the last one was fine.
