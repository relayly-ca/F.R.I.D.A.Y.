# Week 5 — the wake path, the voice gate, tools, the sandbox, and the supervisor

Spec section 6, the second half of the 4-5 row and the week-5 row:

> Voice: Whisper → Kokoro, wake word + clap, speaker ID — under 800ms, hands-free, voice-gated
> MCP tools, OpenHands sandbox, **supervisor** — she can act, and you can kill her

## Goal

This is the week she stops being a very good search interface and starts being able to do
things. Everything that makes that safe arrives in the same week, and that is deliberate:
the voice gate, the tool allowlists, the container boundary and the supervisor are not four
independent features, they are the four sides of the box you are about to put a capability
inside.

The done-when is two clauses joined by an "and", and the second is the load-bearing one:
**she can act, and you can kill her.** Build them in that order and you will spend a night
with an agent you cannot stop. Build the supervisor first and you are supervising your
guesses. The order below interleaves them: gate, then tools, then sandbox, then supervisor,
then turn anything autonomous on.

This is the heaviest week in the schedule and the natural place for it to slip into two. The
split point is after step 4. Nothing after step 4 depends on voice.

## Done when

1. Two claps wakes her from across the room; the wake word wakes her hands-busy; saying "ok"
   returns her to standby.
2. `friday voice enroll` has taken your ten prompts and written a voiceprint.
3. A voice below the cosine threshold is answered but cannot cause anything consequential,
   and the refusal is spoken rather than silent.
4. End of speech to first audio out is under 800ms, measured over 20 turns, p95 not mean.
5. MCP tools are exposed per-agent from `config/agents.yaml`, and no agent can call a tool
   outside its allowlist. There is a test that proves it.
6. OpenHands runs in Docker, produces a branch in `/srv/friday/work`, and cannot reach the
   host filesystem or the network.
7. The supervisor runs as `fridaysup`, health-checks every 30s, and you have watched it
   revert after three induced failures.
8. Modifying a file in `agent/core/` hard-stops her within 30 seconds. You have tried it.
9. An over-budget task is killed, its branch survives, and its vault writes are reverted.
10. The kill switch works from your phone, and the physical button works.

## Prerequisites

- W4 complete. Eval at 20 or better, `known-good` tagged, latency measured per stage.
- Docker working and the `friday` user in the `docker` group — or, better, rootless Docker
  for the OpenHands runtime. Membership in `docker` is root-equivalent on the host, which is
  a real cost to weigh here.
- The mesh from W1, because the phone kill switch rides it.
- A spare GPIO-capable board or a USB button if you want the physical switch this week.

## Steps

### 1. The wake path

Two triggers, spec section 5. Run both — they fail in different directions and that is the
point.

```bash
uv run python -m friday.voice.wake --list-models
uv run python -m friday.voice.wake --train-or-fetch friday   # VERIFY: openWakeWord model source
```

**Wake word**, `openWakeWord`, threshold `0.6` in `config/friday.toml`. For hands-busy.

**Clap**, two claps, then continuous listening until you say "ok". From cc-hermes-cc via spec
section 5, and the reason it earns a slot next to a wake word is precise: a clap physically
cannot false-trigger from speech. A wake word in a room with a television false-fires all
evening; a clap detector does not care what anyone says.

```bash
uv run python -m friday.voice.wake --calibrate     # sets the clap energy threshold for your room
uv run python -m friday.voice.wake --once
```

Calibrate in the room she lives in, with the normal background noise present. A threshold set
in a silent room at midnight fires on a dropped saucepan at breakfast.

### 2. The speaker gate

Spec section 5 and section 9. Resemblyzer voiceprint, ten prompts, once.

> For an always-on agent with shell access, this is a real security control: without it,
> anyone in your house can say the wake word and command your system.

```bash
uv run python -m friday.voice.enroll --prompts 10 --out /srv/friday/db/voiceprint.npy
sudo chown friday:friday /srv/friday/db/voiceprint.npy && sudo chmod 0600 /srv/friday/db/voiceprint.npy
```

Enrol in the same room, at the same distance, with the same microphone you will actually use.
A voiceprint recorded in a headset and used across a room fails constantly and you will be
tempted to lower the threshold, which is the failure this control exists to prevent.

`speaker_threshold: 0.75` and `require_speaker_match: true`. What "gated" means, precisely:

- An unverified voice **is answered**. She is not rude to your guests, and a hard refusal to
  speak makes the system feel broken rather than secure.
- An unverified voice **cannot cause anything consequential**. This is not a policy in a
  prompt — the scrutiny table already carries it as a rule, `unverified_speaker_asks` in
  `config/scrutiny.yaml`, and in week 7 that rule is what enforces it. Until then the same
  check lives in the voice loop itself.
- The refusal is **spoken**, not silent. A silent refusal is indistinguishable from a bug and
  you will spend an hour on it.

```bash
uv run pytest tests/test_speaker_gate.py -q
```

Test it with a recording of someone else, and test it with a recording of you played back
through a speaker. Replay is a real attack against a voiceprint and it is worth knowing
whether yours is vulnerable before you rely on it.

### 3. Under 800ms

W4 step 8 gave you the per-stage breakdown. Now find the 400ms. In the usual order of size:

**End-of-speech detection.** Almost always the biggest. VAD hangover set conservatively at
500-800ms so it does not cut you off. Drop it to 200-300ms and pair it with an
end-of-utterance model rather than a fixed timer.

**Speculative start.** Begin retrieval on the partial transcript before end-of-speech
confirms. Most turns' retrieval is decided by the first few words. Discard and redo when the
tail changes the query — the wasted work is free, it happens during silence.

**Streaming TTS.** First audio out on the first sentence, not on the complete response. This
alone often halves the perceived latency and changes nothing about the total.

**Everything resident.** whisper, Kokoro, `fast`, bge-m3, the reranker. Spec section 1's ~6 GB
resident set is a latency budget, not a memory note.

**`fast`, never `daily`, for voice turns.** `config/agents.yaml` sets `conversation` to
`fast`. Latency is a correctness property here, which is exactly why.

```bash
uv run python -m friday.voice.bench --turns 20 --percentile 95
```

p95, not mean. A mean of 700ms with a p95 of 2.1s feels broken, because you remember the two
seconds and not the eighteen fast turns.

### 4. Hands-free, end to end

```bash
sudo systemctl restart friday-voice.service
journalctl -fu friday-voice.service
```

Clap twice from across the room. Ask something. Say "ok". Then leave it running for a day and
count the false wakes. More than one or two a day and the threshold is wrong; zero across a
whole day with a television on and you have probably set it so high that it misses you too.

**This is the split point.** Everything above is voice; everything below is capability and
containment. If the week is going to become two, break here.

### 5. The graph layer

ADR-0012. Nothing so far owns **how multi-step work moves**, and everything below this point
is multi-step work: a coding task is plan, edit, test, review, branch; a checked vault write
is produce, check, commit. Built without a frame, that logic lands differently in every loop.

It goes here rather than in W6 because checkpointing is what makes step 8's budget kill
coherent. A killed task that resumes at the node it died on is cheap to kill; a killed task
that restarts from nothing is expensive, and an expensive kill is one you avoid using.

```bash
uv run python -m friday.graph --list
uv run python -m friday.graph --run consolidate --dry-run
```

`pydantic-graph` types the nodes, edges and shared state — edges are inferred from a node's
`run()` return annotation. `friday/graph/` adds the three things it does not provide:

**Checkpoints** to SQLite after every node, so a run has a resumable position.

**Resumption**, so a supervisor kill picks up where it stopped.

**The human gate**, which is not a new concept and must not become one. A graph pausing for
approval raises an `ask` through scrutiny's dispatch, into the same inbox, with the same
`ask_expires: false`. There is exactly one place a human is asked, and no second queue that
quietly grows its own timeout.

Two rules bind every graph, and they are checked rather than remembered:

```bash
uv run pytest tests/test_graph.py -q
```

**The writer is never the checker.** A node that writes to the vault or the index has a
distinct checker in front of it, run by a different agent. W3 built the first one; this is
where it becomes a property of the frame rather than of one loop.

**The smallest graph that raises quality.** A graph per loop, not a graph per system. An
oversized graph is harder to reason about than the ad-hoc code it replaced, and the point of
the layer is legibility.

One consequence to get right on the first day, because moving it later is painful:

```bash
sudo -u fridaysup install -d -m 0755 /srv/friday/agent/core/graphs
sudo -u friday test -w /srv/friday/agent/core/graphs && echo "BROKEN" || echo "ok"
```

**Graph definitions live in `agent/core/`.** ADR-0004: she writes skills, tools, prompts and
configs, never the loop that runs them. A graph is a loop that runs things. She reads and
executes them; `fridaysup` owns them; changing one is a human action.

### 6. MCP tools

Spec section 9: "Per-task tool allowlists. Research gets search + read. Coding gets git +
shell on one branch. Never a global grant."

`config/agents.yaml` already holds the allowlists and the `tool_catalog`. The work is making
them enforced rather than declared.

```bash
uv run python -m friday.tools.serve --list
uv run python -m friday.tools.serve --agent conversation --list
uv run python -m friday.tools.serve --agent researcher --list
```

Enforcement lives on the server side, per virtual key. A tool the calling agent is not
allowed is **not present in its tool list at all** — not present-and-refused. An agent that
can see a tool it may not call will spend tokens trying, and a model that has been told about
a capability is a model an injection can talk about.

ADR-0010: matching is on tool name **and input pattern**, not name alone. That is what makes
"shell on one branch" expressible rather than aspirational. The shape is borrowed from
OpenCode's permission config:

```yaml
# config/agents.yaml, tool_catalog entries gain patterns:
#   shell: { deny: ["rm -rf /*", "curl *", "* > /srv/friday/agent/core/*"], allow_cwd: "/srv/friday/work" }
#   git:   { deny: ["push origin main", "push * main", "checkout main"] }
```

```bash
uv run pytest tests/test_tool_allowlist.py -q
```

That test is not optional and it is not a formality. It must assert, per agent, that a
denied tool is absent from the served list and that a denied input pattern is refused even
when the tool is allowed.

### 7. OpenHands

Spec section 1 and ADR-0010: OpenHands owns the autonomous-coding slot, and the reason it
does is the Docker boundary. Not its permission model — its container.

```bash
# VERIFY: current image tag and runtime image from the OpenHands documentation.
sudo docker pull docker.all-hands.dev/all-hands-ai/openhands:latest
sudo install -d -m 0750 -o friday -g friday /srv/friday/work
```

Run it with the boundary actually in place. Every flag below is doing something:

```bash
sudo -u friday docker run -d --name friday-openhands --restart unless-stopped \
  --network none \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=512m \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  --pids-limit 512 \
  --memory 8g --cpus 4 \
  -v /srv/friday/work:/workspace:rw \
  -p 127.0.0.1:3001:3000 \
  # VERIFY: OpenHands needs a model endpoint. Reaching LiteLLM from --network none
  # requires an explicit bridge to 127.0.0.1:4000 and nothing else. Do not solve this
  # by dropping --network none.
  docker.all-hands.dev/all-hands-ai/openhands:latest
```

That `# VERIFY` note is the real work of this step, and it is where the week most often goes
wrong: the fastest way to make OpenHands reach the model is to give the container the host
network, which deletes the boundary that is the entire reason OpenHands has the slot. Give it
a bridge to LiteLLM and nothing else, or run LiteLLM's port into the container's namespace
explicitly.

Branch only, human merge. Spec section 9: "Not once, not for small things."

```bash
sudo -u friday git -C /srv/friday/work config receive.denyCurrentBranch refuse
sudo -u friday git -C /srv/friday/work config branch.main.pushRemote no_push
```

Test the boundary before you trust it:

```bash
sudo docker exec friday-openhands sh -c 'ls /srv/friday 2>&1 | head -1'      # must fail
sudo docker exec friday-openhands sh -c 'curl -m 3 https://example.com 2>&1 | head -1'  # must fail
sudo docker exec friday-openhands sh -c 'touch /workspace/x && echo writable'           # must succeed
```

Forgejo, for the remote she pushes branches to and you merge from:

```bash
paru -S --needed --noconfirm forgejo   # VERIFY: package name
sudo systemctl enable --now forgejo    # bind 127.0.0.1; reachable over the mesh only
```

### 8. The supervisor

Spec section 9, and it is specified precisely enough to be a checklist:

> The supervisor: ~150 lines, different user, outside her reach. Health-checks every 30s,
> reverts to last-known-good after three failures, kills over-budget tasks, hard-stops if
> `agent/core/` is modified, and only advances the `known-good` tag after a full eval pass.

Six behaviours, about 150 lines, running as `fridaysup`. Keep it that size. A supervisor with
enough surface area to have its own bugs is not a supervisor (ADR-0009).

It must not import `friday.*`. `pyproject.toml` lists it as a separate top-level package for
exactly this reason: importing the code it polices inherits that code's surface area and its
dependencies, and a crash in a retrieval library then takes down the thing that was supposed
to notice.

```
1. health check      every 30s. `bash install/preflight.sh --quiet` plus a liveness
                     probe per managed unit. Preflight is already quiet-capable and
                     fast because of this.
2. revert            three consecutive failures -> `git checkout known-good`, restart
                     the managed units, write to the inbox. Not four, not "three in a
                     row within a window" - three consecutive.
3. budget kill       tokens and wall clock per task, from config/agents.yaml. SIGTERM,
                     sigterm_grace_s, then SIGKILL. config/friday.toml [budgets].
4. core immutability hash every file under agent/core/. Any change -> hard stop, every
                     managed unit, immediately. Not a warning, not a revert - a stop.
5. known-good gate   advance the tag only after `make eval` passes. ADR-0009: without
                     this, "last-known-good" means "last thing that started without
                     crashing", and reverting to it restores a system that boots and
                     retrieves badly.
6. kill switch       phone over the mesh, and a physical button.
```

```bash
sudo install -d -m 0750 -o fridaysup -g fridaysup /srv/friday/logs/supervisor
sudo bash install/04-services.sh
sudo systemctl enable --now friday-supervisor.service
journalctl -fu friday-supervisor.service
```

The supervisor's own unit deliberately carries **less** sandboxing than the units it
supervises. ADR-0004 says why: sandboxing the guard alongside the guarded defeats it. The
polkit rule from `install/01-users.sh` is the whole of its elevated privilege — it can manage
`friday-*` units and nothing else, and it cannot manage `friday-supervisor.service` itself,
so nothing it supervises can stop it.

Now induce each failure. A supervisor you have not watched work is a supervisor you are
guessing about:

```bash
# 2. Revert after three consecutive failures.
sudo systemctl stop friday-llama@daily
# wait 90 seconds, watch the journal count 1, 2, 3, then revert
journalctl -u friday-supervisor.service --since '2 minutes ago' | grep -E 'health|revert'
sudo systemctl start friday-llama@daily

# 4. Core immutability. This must hard-stop her within 30 seconds.
sudo touch /srv/friday/agent/core/canary
journalctl -u friday-supervisor.service --since '1 minute ago' | grep -i 'core'
systemctl list-units 'friday-*' --no-pager
sudo rm /srv/friday/agent/core/canary
sudo systemctl start friday-hermes friday-openjarvis

# 3. Budget kill. Branch survives, vault writes revert.
uv run python -m friday.tools.testtask --burn-tokens 999999
sudo -u friday git -C /srv/friday/work branch --list
sudo -u friday git -C /srv/friday/vault log --oneline -1
```

`keep_branch_on_kill: true` and `revert_vault_on_kill: true` in `config/friday.toml`. A
killed task leaves its branch for you to inspect, has its vault writes reverted, and reports
to the inbox. Nothing half-applied is the requirement, and half-applied is the default
outcome if you do not build for it.

### 9. The kill switch

Spec section 9: from your phone plus a physical button.

```bash
# Phone: over the mesh, never a port forward. A Matrix command to the friday account
# handled by the supervisor, not by Hermes - a kill switch routed through the thing it
# kills is not a kill switch.
uv run python -m supervisor.killswitch --test

# Physical: config/friday.toml [kill_switch] gpio_button = true, gpio_pin = <n>
${EDITOR:-nano} config/friday.toml
sudo systemctl restart friday-supervisor.service
```

The phone path must not depend on Hermes, OpenJarvis, or the model being healthy. The whole
point of a kill switch is that it works when everything else has stopped working.

## Failure modes

**The speaker threshold gets lowered until it stops being annoying.** The single most likely
way this week's security property is quietly deleted. If 0.75 rejects you constantly,
re-enrol in the room and with the microphone you actually use — do not move the number. A
threshold tuned down to 0.5 accepts roughly anyone.

**The wake word fires all evening with a television on.** Expected, and it is why the clap
exists. Raise the wake-word threshold and rely on the clap for across-the-room; the clap
cannot false-trigger from speech.

**Latency is met at the mean and not at p95.** You have optimised the common path and left a
cold-start on the rare one. Usually a model that got evicted. Check what is resident.

**OpenHands cannot reach LiteLLM, so `--network none` gets removed.** This is the week's
worst outcome and it looks like a fix. The container boundary is the entire reason OpenHands
holds the slot (ADR-0010). Give it a bridge to `127.0.0.1:4000` and nothing else.

**The `friday` user is in the `docker` group and that is now root on the host.** Weigh it.
Rootless Docker for the OpenHands runtime is the better answer and it costs an evening.

**The supervisor imports `friday.config`** to read `friday.toml` "just for the budgets". Now
a broken dependency in the agent's code takes down the supervisor. Parse the TOML with the
stdlib; `tomllib` is in 3.11+ and the supervisor needs about twelve lines of it.

**The supervisor reverts and the revert makes things worse.** `known-good` was tagged on a
commit that started cleanly but retrieved badly. ADR-0009 exists to prevent this: the tag
advances only after a full eval pass. Check that `make known-good` really runs the eval and
really fails closed.

**The kill switch is routed through Hermes.** It then works exactly when you do not need it.
Route it to the supervisor.

**Three failures counted across a window rather than consecutively.** A flapping unit never
reaches three-in-a-row and never triggers the revert, or a healthy unit with one blip
accumulates to three over an hour and gets reverted for nothing. Consecutive.

## Do not do yet

- **No scrutiny.** W7. Nothing decides on its own yet: every action this week is triggered by
  you, in a turn, in front of you. That is the correct amount of autonomy for the week you
  first build a kill switch.
- **No unattended overnight run.** Not once, not "just to see". Spec section 10: your first
  unbounded run will burn 2M tokens for nothing. The budgets exist now, and they have not
  been exercised against a real overnight task yet.
- **No mode detection.** W6.
- **No skill optimisation.** W8, and it is bounded precisely by ADR-0004, which you have just
  finished verifying.
- **Do not merge an agent branch without reading it.** Not once, not for small things.
- **Do not grant a tool globally** because two agents both need it. Two allowlist entries.
- **Do not disable the supervisor to debug something.** Stop the unit it is complaining about
  instead.
